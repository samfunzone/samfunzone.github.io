# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Samritha's Fun Zone

## Project overview
A kids' React + Vite app running at `http://localhost:3000`.
Each game lives in `src/components/` as its own self-contained file.
Global styles are in `src/App.css`. Shared confetti utility is in `src/utils/confetti.js`.

## Commands
```bash
npm run dev      # dev server on port 3000 (set in vite.config.js)
npm run build    # production build → dist/
npm run preview  # preview the production build locally
npm run lint     # ESLint (flat config, eslint.config.js)
```

## Adding a new game
1. Create `src/components/MyGame.jsx`
2. Add its CSS section to the bottom of `src/App.css`
3. Import and add an entry to the `TABS` array in `src/App.jsx`

## Modernizing a game's visuals

## Architecture notes
- **Tabs**: `App.jsx` renders one tab at a time from the `TABS` array — no router needed.
- **Confetti**: import `launchConfetti(x, y, count)` from `src/utils/confetti.js`. The `confettiFall` keyframe is defined in `App.css`.
- **Three.js (Squishy Stuff)**: scene is created in a `useEffect` on phase change, cleaned up on unmount. Scale state is stored in a `ref` (not React state) so the render loop can read it without re-renders. Renderer is `alpha: true` with no `scene.background` — the dreamy gradient backdrop is CSS on `.three-mount` (don't reintroduce a scene background or it covers it). Material is `MeshPhysicalMaterial` with clearcoat for the jelly gloss; shadow map type must be `PCFShadowMap` (`PCFSoftShadowMap` was removed in three r183). **Emoji stage**: the outer `.sq-emoji-stage` owns the drop-in entrance (`key={emoji}` replays it) and the inner `.squishy-emoji-big` owns the inline `scale(ex, ey)` squish transform — never put an animation on the inner span (a running CSS animation overrides inline `transform`). The emoji squishes from `transform-origin: 50% 100%` (ground-planted) with a `.sq-emoji-shadow` ellipse whose `scaleX` tracks `ex` and opacity tracks `1/ey`; the stage's `margin-bottom` keeps the emoji clear of the bottom ↕ handle. `SquishBurst` particles replay via `key={burstId}` remount and carry base `opacity: 0` (they end invisible — reduced-motion safety); ambient `.sq-bubble` spans use deterministic sizes/timings and also rest at `opacity: 0`. Color swatches use inline radial gradients from `src/utils/color.js` helpers. All keyframes are `sq*` in App.css with a `prefers-reduced-motion` block disabling them.
- **SVG dolls (Dressing Dolls)**: layer order matters — SceneBackground → HairBack → Body → Shoes → Clothing → HairFront → HeadSkin → FaceFeatures → Hat → Accessory. Key rules:
  - HeadSkin renders after HairFront so it covers the face center.
  - Shoes render **before** Clothing so skirts/bottoms cover boot tops naturally.
  - Hats are shifted ~8px lower than head-top (band sits at y≈37–55) so they look seated on the hair.
  - Tops/bottoms must fully cover the body rect (torso x=58–142). Jeans and shorts use a center panel rect to close the gap between the two leg rects.
  - Face customization: `eyeStyle` (normal/wide/happy/sleepy/winking), `browStyle` (normal/raised/furrowed/arched), `mouthStyle` (smile/grin/surprised/pouty) are stored in `outfit` state alongside clothing fields.
  - Scene backgrounds (`SceneBackground` component): 6 options (none/beach/park/school/party/meadow) stored in separate `scene` state.
  - Presets (`PRESETS` array): each entry has `id`, `label`, `scene`, and a partial `outfit` object merged over current state (skin tone preserved). Beach and Party presets auto-switch scene.
  - Randomize: `randomFrom(arr)` helper; hat/accessory weighted 2× toward `'none'` to avoid clutter.
- **Making Boba pearls**: pearls drop 5 at a time (max 35). Before shake they use a 5-per-row grid (cx=48, step=16). On shake, positions come from a dense slot pool — all valid 16px-spaced slots inside the tapered cup are pre-generated, shuffled, and the first N taken. Cup taper: top x=22–138 at y=40, bottom x=40–120 at y=282 (`t=(y-40)/242`, `lx=22+18t`, `rx=138-18t`). Always clamp slice with `Math.min(pearls.length, allSlots.length)` and null-guard each position.
- **Making Boba visuals**: realistic look built from SVG gradients only — no SVG filters (mobile perf). All defs ids prefixed `boba-`; tea-tinted gradients (`boba-tea-grad`/`boba-foam-grad`/`boba-straw-grad`) recompute stops from `tea.color` via the `mix`/`lighten`/`darken` helpers in `src/utils/color.js` (shared with Yummy Food). Pearls carry a `top` field (topping id) that selects their `boba-pearl-{id}` gradient — never spread `activeTop` after `id` (duplicate-key bug). The dome lid + straw render **only when `done`**; cup is open while building. Cup size uses the `--sc` CSS var on `.boba-cup-wrap` (shake/float keyframes reference `var(--sc,1)`) — don't set inline `transform`. Animations are `boba*` CSS keyframes in App.css: mount-once entrances (pearl/ice drop, lid pop, straw insert) rely on stable keys + `animation-fill-mode: backwards`; the pour stream replays via `key={tea.id}` remount; animated SVG children need `transform-box: fill-box`. A `prefers-reduced-motion` block disables them all.
- **Number Detective**: guess-the-number game. `LEVELS` array has 4 entries (max: 100/1000/10000/100000) each with a `rank`, `emoji`, `color`, and `optimal` (binary-search ceiling). `PALETTE` maps color names to `{bg, border, accent, badge}`. `proximity(guess, secret, max)` returns a hot/cold label+emoji+color based on distance as a fraction of max (thresholds: 2%/8%/20%/40%/60%). Range bar shows a **positioned segment** (`left: segLeft%`, `width: segWidth%`) representing the remaining `lo`–`hi` window on the full number line — not a fill from the left. **Hard Mode**: toggle on level-select screen; during play hides the `lo`/`hi` number labels on the bar, always shows the latest clue row, and hides all previous clues behind a `💡 See N previous clues` peek button that auto-collapses on the next guess. Win screen shows a `🕶️ Hard Mode cleared!` badge when solved without giving up.
- **Bubble Pop**: timed arcade popper (45s, `GAME_SECONDS`). Bubbles spawn on a `setInterval` (rate from the chosen `SPEEDS` entry, capped at `MAX_BUBBLES`) and rise via the `bubRise` CSS keyframe — travel distance is the `--riseH` var on `.bub-arena` (640px desktop / 560px mobile; must exceed arena height + bubble size + spawn offset). The **outer** `.bub-float` div owns the rise transform and the **inner** `.bub-sway` div owns the side sway — never merge them (one running animation overrides the other transform). Bubbles are centered on their `x`% via negative `marginLeft`, not `translateX` (the rise animation owns `transform`). `onAnimationEnd` checks `e.animationName === 'bubRise'` before counting an escape. Pop position is read with `getBoundingClientRect()` at pointerdown (live mid-animation position); bursts/floaters render as absolutely-positioned arena children removed by timeout. Bubble types from `makeBubble` weights: normal (+10, or +15 when `size < 58`), star (+40 + confetti), rainbow (clears every on-screen bubble via `querySelectorAll('.bub-float')` + `data-id`), grumpy (−15, combo reset, `bub-shake` on the arena). Combo lives in `comboRef` (1.5s window): ×2 at 4 chain, ×3 at 8; the badge re-pops via `key={combo}`. SVG gradients (`bub-` prefix) render once in a hidden `<svg>` (ids are page-global); soap-bubble look = low-opacity tinted radial body + iridescent arc stroke + white specular ellipses. Menu/done screens are `.bub-overlay` glass panels **inside** the arena. Burst ring/droplets/floaters end invisible, so they carry base `opacity: 0` (reduced-motion safety). All keyframes are `bub*` in App.css; the reduced-motion block intentionally keeps `bubRise` running (the game needs movement) and disables only decorations.
- **Word Search**: `THEMES` (4 word pools) × `LEVELS` (easy 8×8 across+down, medium 10×10 +diagonal, hard 12×12 all 8 directions incl. backwards). `buildPuzzle` retries whole-grid generation (50 attempts; per word 250 random placement tries, longest first, overlaps allowed on matching letters) then fills gaps with random letters. Cells use flat indices `r*size+c`. Drag-select: pointer events live on the `.ws-grid` container only — cells are `pointer-events: none` and the grid is `touch-action: none`; the cell under the pointer comes from bounding-rect math, and the live selection is mirrored in `selRef` because pointermove state updates are batched — `onUp` must read the ref + its own event coords, never `sel` state, or fast drags end one cell short. `lineCells` snaps the drag to H/V/diagonal. Matching is string-based (forward or reversed) against unfound words, so an accidental second occurrence also counts. Found cells/chips get inline gradients from `FOUND_COLORS` via `lighten`/`darken`; tile entrance staggers by `(r+c)*26ms` and replays via `key={gameId}` on the grid. Hint pulses a word's first cell for 2.6s; win stars = 3/2/1 for 0/≤2/3+ hints. Keyframes are `ws*` in App.css; in the reduced-motion block `.ws-chip-found::after` needs the static `width: 80%` override (the `wsStrike` animation ends visible).
- **Unscramble Words**: `CATEGORIES` (4 pools of `{w, e}` word+emoji entries); a game picks `ROUNDS` (8) random words sorted shortest→longest. Letters are tile objects `{id: '${round}-${i}', ch}`; `rack` and `slots` arrays hold ids (duplicate letters safe), and moving a tile between containers remounts it, replaying `unTilePop`. Tap a rack tile → first empty slot; tap a slot tile → back to rack; when slots fill, the guess auto-checks. `status` drives the slot-row class: `correct` (green `unCheer` stagger via inline delay), `wrong` (`unShake`, 600ms then back to `building` with letters kept in place), `skipped` (tiles auto-arranged into the answer, shown orange, then advance). Scoring: `max(100 − 25·hintLevel, 25) + streak·10`; hints are two-level (1 = emoji reveal in the bubble, 2 = ghost first letter in slot 0); skip resets the streak, wrong attempts don't. Category accent flows through `--un-accent` + CSS `color-mix` (no JS color math). Keyframes are `un*`; `.un-gain` carries base `opacity: 0` (it ends invisible — reduced-motion safety). Shared `shuffle` helper lives in `src/utils/shuffle.js` (used by both word games).
- **Joke Machine**: jokes are served from a shuffled deck (`useRef`). When the deck empties it reshuffles, avoiding the last-shown joke at position 0.
- **Drawing (Draw Something)**: art-studio paint tool over an HTML `<canvas>` (700×400). The drawing surface stays raster; all chrome is SVG/CSS (ids prefixed `draw-`). **Colour picker** = `PaletteSVG`, a wooden-board SVG with 12 swatches. The swatches render as the **active tool** (`PaletteShape`: colored pencils/crayons/brushes/paint-tubes, one per colour) so the palette "becomes" the selected medium; for the Eraser they fall back to glossy radial-gradient paint blobs (`draw-blob-{i}` gradients built from `lighten`/`darken` in `src/utils/color.js`). The inner group is keyed by `tool` so it remounts on a medium switch; the active blob shows a `drawDabPop` selection ring, and `.draw-blob-inner` scales on hover (needs `transform-box: fill-box`). A wet "current paint" dab on the board (`.draw-paint-dab`, keyed by `color` so it re-pops) and the per-medium `ToolGlyph` icons both recolour to the selected colour. **Mediums** (`MEDIUMS` array → `tool` state): pencil/crayon/brush/oil/erase, each with a `widthMul` + `alpha`; `drawSegment(ctx,a,b)` renders the active medium's stroke (crayon = jittered waxy passes, pencil = fine line + faint grain, oil = thick body + impasto highlight/shadow edges, brush = smooth, erase = white). Drawing tracks `lastPos` in a ref and strokes discrete segments (a tap calls `drawSegment(p,p)` for a dot). **Picking a colour while erasing auto-switches to brush.** `BrushPreview` is a live SVG stroke sample reflecting colour + size + medium (deterministic grain — no `Math.random()` in render; the canvas-painting jitter *does* use random, which is fine since it's an event handler, not React render). The canvas sits in a CSS wooden frame (`.draw-stage`, `drawStageIn` entrance). Keyframes are `draw*`; a `prefers-reduced-motion` block disables them. Undo snapshots `ImageData` to a `history` ref (erase strokes snapshot too); Save exports PNG + confetti.
- **Family Feud**: survey-style guessing game. `QUESTIONS` array (~75 entries) each has a `question` string and `answers` array of `{ text, points, aliases[] }`. `norm()` lowercases and strips punctuation before comparing guesses to aliases. Game picks `TOTAL_ROUNDS` (5) questions at random per game via a shuffled index array in a `useRef`. Phases: `'playing'` → `'round-end'` → `'game-end'`. Three strikes end the round early; "Reveal Answers" button also ends the round. Revealed slots show rank badge (`#1`, `#2`, …) + answer text + points pill. Board shakes on a wrong answer (`feudShake` keyframe). All questions are family-friendly — questions with alcohol, adult relationships, workplace, or other adult-only content are excluded.
- **Enchanted Garden**: seed picker shows 6 flower types (Sunflower, Rose, Tulip, Daisy, Lavender, Cherry Blossom). Each has its own `FlowerBloom` SVG component. `PlantSVG` uses per-seed `stemColor`/`leafColor`/`budColor`/`budTip`.
- **Magic Loops**: canvas-based loop drawing with 4 color palettes (Rainbow, Sparkle, Ocean, Fire) and a magic meter; filling the meter triggers confetti.
- **My Room**: drag-and-drop SVG room decorator — choose wall color, floor style, then drag furniture and decor items onto the canvas.
- **Yummy Food SVGs**: all 8 foods (Pizza, Burger, Sandwich, Fries, IceCream, Cake, Taco, Cookie) use ingredient toggle via `added` Set passed as prop. The **Cookie** (`CookieSVG`) is a gradient-only chocolate-chip cookie with a homemade wavy baked edge; toppings (chips, candy buttons, nuts, sprinkles, icing drizzle) are gated on `h('dough')`, with the usual done-screen sheen/steam/sparkles. Required: dough + chips. Each Viz also takes a `done` prop (set on the done screen) that turns on `Sparkles` (all foods) and `Steam` (hot foods: pizza, burger, taco, fries).
  - **Visuals**: gradient-only realism, no SVG filters or CSS `drop-shadow` (mobile perf). All defs ids prefixed `food-`. Shared defs helpers at the top of the file: `VGrad` (vertical 3-stop body fill), `Glossy` (radial highlight at 35%/30%), `Shadow` (`food-shadow` ground ellipse), plus `Sparkles`/`Steam` decoration components. Color helpers imported from `src/utils/color.js`.
  - **Animations**: every ingredient renders inside `<g className="food-ing">` — mount-once drop-in keyframe (`foodIngDrop`) with `animation-fill-mode: backwards`, staggered via inline `animationDelay`. These groups must NOT carry a `transform` attribute (a running CSS animation overrides it) — nest an inner `<g>` for attribute transforms (see fries rotation, sparkle translate). All keyframes are `food*` in App.css (`foodIngDrop`, `foodPanelIn`, `foodSteamRise`, `foodFlameFlicker`, `foodSparkle`, `foodServePulse`, `foodFloatUp`, `foodCheckPop`, `foodEmojiBounce`, `foodPickPop`, `foodDripGrow`, `foodSheenSweep`, `foodTwinkle`, `foodWiggle`, `foodTada`, `foodHappyBob`, `foodCookBounce`, `foodCookRise`); a `prefers-reduced-motion` block disables them all. Build/pick/done panels remount with `.food-panel-in` (`key={food.id}` on `.food-layout`); pick buttons pop in staggered via `.food-pick-btn` + inline `animationDelay`.
  - **Extra animation classes**: `.food-drip` (melty cheese/cone drips, mount-once `scaleY` grow — needs `transform-box: fill-box; transform-origin: center top`; ends visible so no base opacity); `.food-sheen` (gradient bar swept over the finished pizza inside `food-pizza-clip`; carries base `opacity: 0` because it ends invisible); `.food-twinkle` / `.food-wiggle` (done-only garnish loops — applied to an **inner** wrapper `<g>` so they never clash with the `food-ing` animation or attribute transforms on children); `.food-done-viz` (done-screen wrapper: `foodTada` entrance chained with infinite `foodHappyBob` via comma); `.cook-emoji` + `.cook-rise` (cooking-overlay bounce + rising emoji particles; the overlay has `overflow: hidden`).
  - **Done-only garnish**: burger toothpick + cherry tomato, sandwich club pick + olive, ice-cream cone melt drips, pizza sheen sweep, salt twinkle, cherry/jalapeño wiggle — all render or activate only when `done`.
  - **IceCream**: dynamic `viewBox` grows upward as scoops stack (`minY = Math.min(topY - R - 35, 0)`, `vh = 290 - minY`). Waffle cone lines wrapped in `<g clipPath="url(#food-cone-clip)">` so lines never extend outside the cone triangle. Scoops keyed by flavor id with `transition: cy` so they glide when a lower scoop toggles. Per-flavor surface detail comes from `ScoopTexture`, clipped per scoop via an inline `clipPath` id `food-sclip-{id}`; melty overhang ellipses draw **before** the scoop circle so it covers their tops.
  - **Burger**: layers stacked with imperative `curY` counter (`let curY = 234; const nextY = h => { curY -= h; return curY; }`). Each ingredient height subtracted in render order; top bun uses final `curY`.
  - **Sandwich**: same `curY` stack pattern as Burger (starts at 232: bread 20 → ham 16 → cheese 10 → lettuce 14 → tomato 12 → cucumber 10 → mayo 8 → domed top slice). Both slices render from the single `bread` ingredient; mayo is a wavy closed ribbon built from alternating `q` bezier curves.
  - **Fries**: deterministic fry fan — `x: 60+i*9`, `top: 34+((i*23)%20)`, `rot: ((i*37)%15)-7` — never `Math.random()` in render. Render order: carton back panel → fries → salt/cheese/herbs → carton front panel, so fry bottoms stay hidden inside the box (no clip needed). Fry toppings render only when `fries` is also added; ketchup is a separate dip cup at the right.
  - **Cake**: 3 tiers computed via `lty = i => 256 - (i+1) * LAYER_H` (LAYER_H=44), sitting on an always-rendered pedestal stand (viewBox is 200×292). Each layer: gradient rect + highlight stripe + piped pearl dots + frosting ellipse cap + drip paths with glossy tip beads. Candle flames are wrapped in `g.food-flame` (flicker keyframe; needs `transform-box: fill-box; transform-origin: 50% 100%`) together with a `food-glow` radial halo. Star decorations are gold-gradient `STAR` paths, not emoji text.
  - **Taco**: side-view folded shell in two halves — dark back half (`M30,166 Q110,30 190,166`, shadow-toned gradient) renders first, fillings spill out between the halves, light front half (`M22,168 Q110,62 198,168`) renders **last** and covers all filling bottoms (no clipPath needed). Meat and lettuce are thick stroked paths along the fold curve (`strokeLinecap="round"`) with crumble circles / two rows of ruffle bumps placed via the quadratic-bezier helper `lq(t)`; cheese is scattered shredded rects; sour cream is a dollop cluster with drizzle tails; jalapeño slices crown the pile and wiggle when `done`. Filling render order (meat → lettuce → tomato → cheese → sourcream → salsa → jalapeño) is also the visual stacking — keep fillings in the y≈70–115 band so the front-shell edge (y≈115 at center) hides their bottoms.
- **Tamil Tango** (component `TamilLetters.jsx`): a "classroom in disguise" that teaches the Tamil writing system. **Sound is currently disabled** via the `SOUND_ENABLED = false` flag (clip/TTS pronunciation was inaccurate — see README TODO); `say()` early-returns, the 🔊 buttons are commented out, and **Listen & Find** is commented out of the `MODES` array (its component stays in the file, unreachable). The audio wiring below describes the intended re-enabled behaviour. — combining a மெய் consonant with a உயிர் vowel to form a உயிர்மெய் letter (`க் + ஆ = கா`, 18 × 12 = 216). Self-contained `TamilLetters.jsx`, classes prefixed `tl-`, accent via the `--tl-accent` CSS var. **Sound = pre-recorded clips, not live TTS**: 246 accurate native-voice MP3s live in `public/audio/tamil/` — `ta_v{vi}.mp3` (12 உயிர்), `ta_m{ci}.mp3` (18 மெய் pulli sounds), `ta_c{ci}_v{vi}.mp3` (216 உயிர்மெய்). The component builds a `SOUND` Map (Tamil glyph → clip filename: `u.base → ta_v{vi}`, `m.pulli → ta_m{ci}`, `compose(m,u) → ta_c{ci}_v{vi}`) and a `say(text)` helper that plays `${import.meta.env.BASE_URL}audio/tamil/…` via `playClip` and falls back to browser TTS only if a clip is missing. `playClip(url, fallbackText)` in `src/utils/speech.js` caches `Audio` objects, cancels any in-flight clip/TTS, and on play/load error speaks `fallbackText`. The clips were generated once from Google's `tl=ta` TTS endpoint (one-off generator scripts, since removed) because earlier pure-`speechSynthesis` playback was inaccurate/missing on most devices. Romanized captions (the `tr` fields) still show on every letter for reading support.
  - **Data**: `UYIR` (12 `{ base, sign, tr }` — `sign` is the combining vowel mark, empty for அ) and `MEY` (18 `{ pulli, cons, tr }` — `pulli` is the dotted form, `cons` the bare inherent-'a' form). `compose(m, u) = m.cons + u.sign`; `roman(m, u) = m.tr + u.tr`. `ROUNDS = 10`.
  - **Three modes** off a start screen (`mode` state: null/learn/mix/listen; every mode has a `← Modes` back button): **Learn Grid** is the full 216-cell uyirmey reference table (`gridTemplateColumns: auto repeat(12, 1fr)`); tapping a body cell sets `sel` + speaks `compose`, the breakdown bar shows `pulli + base = compose 🔊 roman`; row/column headers speak the consonant/vowel alone; cells stagger in via `tlGridIn` with inline `animationDelay: (r+c)*12`. **Mix It!** is the core quiz — `makeOptions(m,u)` builds 4 choices = correct + 2 same-consonant/different-vowel look-alikes (reinforces vowel signs) + 1 same-vowel/different-consonant, shuffled; correct → speak + `tl-merge` + confetti + score `max(100 - wrongs*25, 25) + streak*10`, wrong → `tlShake` + streak reset (retry allowed). **Listen & Find** speaks the target on each round (`useEffect` keyed on `round`/`done`, eslint-disabled exhaustive-deps), 6 option tiles with romans hidden until answered, big 🔊 replay; shows a "needs sound" banner when `noVoice`.
  - Shared `TopBar`/`Dots`/`WonScreen` follow the Unscramble pattern (phases, `timeouts` ref + `later()` cleanup, recap, star rating 3/2/1). Keyframes are `tl*` in App.css (`tlPop`, `tlGridIn`, `tlMixMerge`, `tlCheer`, `tlShake`, `tlGain`); `.tl-gain` carries base `opacity: 0` (ends invisible) and a `prefers-reduced-motion` block disables them all. Mobile tweaks (smaller grid cells/tiles) live inside the `max-width: 600px` query.

## Styling conventions
- Every game card uses `.card` + `.card-{color}` (red/blue/green/purple/orange).
- Shared button styles: `.btn .btn-{color}`.
- Game-specific styles are prefixed with the game name (e.g. `.boba-`, `.doll-`, `.food-`).
- Mobile breakpoint at `max-width: 600px` at the bottom of `App.css` — reduces card/tab padding, stacks `.room-palette` full-width, narrows grids. SVGs in food/boba/doll components carry `style={{ maxWidth: '100%', height: 'auto' }}` so they scale on small screens.
- Horizontal scrolling strips (e.g. `.doll-scene-strip`) must NOT have a `max-width` — use `overflow-x: auto` alone so buttons are never clipped on narrow screens.
